# 前三项审查问题的修复与验证

版本：`0.2.0-alpha.7 / sidebar-p5`。日期：2026-10-31。

范围仅限 [独立验证报告](2026-10-31-p5-independent-validation.md) 的前三项。第 4–7 项仍留在原报告中，不在本次完成范围。

## 现在的行为

1. **修复要求能够转交。** “帮我修复保存失败的问题”“请定位并修复失败的检查，保留已有要求及数据”等明确要求，按原话转交主对话。建议按钮仍只填入输入框，用户发送才转交。混合疑问继续澄清；否定、引用、条件和未明确对象不会自动触发开发。升级前保存的单条明确修复澄清可继续确认，但旧依据不能直接套到新状态。
2. **旧故障分析不再冒充当前状态。** 卡片、历史与追问复用相同的文件、需求、偏好和故障记录判定。追问同时携带最新检查记录，明确“没有失败记录不等于功能已验收”。关联材料改变后不复用旧追问缓存；生成期间发生变化的回答标为历史，同一请求重试也不会把旧回答重新标成当前。
3. **排障解释与下一步建议在同一张卡片。** 当前进展中优先显示最新排障卡片；同一分析的普通文本副本不再重复显示，相关建议紧接解释内容，整张卡片位于项目要求列表之前。其他讲解、历史记录、底部输入框和主动发送方式保留。

没有新增自动摘要或自动修复，也没有恢复主 AI 原话或“查看依据”面板。

## 验证

- **144 项测试通过**，包括 5 项新增回归：常用修复表达按原话且仅转交一次；讨论/否定/条件/模糊对象保护与混合确认；旧澄清升级及过期依据保护；检查通过后的卡片/历史/追问和缓存时效；讲解生成途中检查改变。
- 真实 Harness `0.2.1-rc.3` 隔离测试通过。使用本地固定模型，不调用真实提供方，不写日常聊天。卸载取消、重载恢复及不重复转交断言通过。
- 1050 × 820 视窗下的 **369 px 侧栏**实测：排障卡片 1 张、重复文本卡片 0 张；建议填入后转交回执 0 条；用户发送后出现 1 条“已送达主对话”，原话保留，输入框清空。底部输入框可见，无横向溢出。
- 本机安装已升级，原 profile 有备份，旧记录和存储位置保留；安装后文件核对见下方验证结果。日常 Harness 需完全退出并重新打开加载新包。

这证明上述样例中的分流、状态和交互修复，不证明真实模型讲解质量或真人理解提升。

# 侧栏真实模型评测

日期：2026-11-03。模型：DeepSeek 账号路由 `deepseek-flash`（与本机 Harness 主对话所选模型一致）。用例见 [evals/sidebar/cases.json](../../evals/sidebar/cases.json)，运行 `npm run eval:sidebar`。

评测只复制已登录的推理账号到临时目录（权限 0700，结束即删除），不复制会话、工作区或个人配置；结果文件不含凭证，保存在被 Git 忽略的 `evals/runs/`。

## 评测内容

| 部分 | 用例 | 检查什么 |
| --- | --- | --- |
| 讲解是否标出可发送的改法 | 8 | 该给改法时给、纯概念问题不给；改法以“请”开头、包含关键对象；标记不残留在正文 |
| 代写要求是否忠于原意 | 6 | 以“请”开头、300 字内；保留数字、否定和条件；不添加原文没有的功能 |
| 概览分层与完成程度 | 2 个小项目、12 个文件 | 每个文件的层和完成程度；“还没做”包含该有的部分且不重复；描述不以“可能”开头；产品名不照搬文件夹名 |

## 结果

最终两轮完整运行均为 **讲解 8/8、代写 6/6、概览 2/2（12/12 个文件）**。规则通过后又逐条人工阅读了原始输出：

- 讲解：材料不足时会明说“无法确认”，不编造；改法都具体、可执行。
- 代写：数字、否定和条件全部保留；只额外加“其他内容不要动”这类收窄范围的话，没有扩大范围。
- 概览：示例用户、“待开发”占位都正确判为“模拟”；Supabase 登录判为外部服务。单次概览耗时 12–32 秒。

## 评测中发现并已修复

1. 生成概览的输出上限 2200 不够，新格式被截断（用户实测发现，已改为 8000，截断时明确提示）。
2. 开发资料（文档、设计稿、测试脚本）也被标了“能用 / 模拟”，没有意义：保存时去掉，界面也不显示。
3. 已有占位的部分又出现在“还没做”里：提示词要求标为“模拟”，保存时再按名称去重。
4. 产品名可能照搬传入的项目名：提示词要求根据内容判断。

另外修正了一条有歧义的用例（渲染函数原本写成注释，模型判为“模拟”其实合理）。

## 局限

用例由开发者编写，数量少，只覆盖中文、两个小项目和单一模型；每条只跑了 1–2 次，没有统计波动。它能发现格式、截断和明显的判断错误，不能代替非技术用户的真实试用。

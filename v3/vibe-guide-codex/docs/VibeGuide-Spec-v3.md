# Vibe Guide v3 实现约束与验收 Spec

日期：2026-11-12。约束依据：同目录 PRD v3、技术设计 v3。本文件定义实现必须满足的行为；功能状态另见实施记录，不以文档代替运行证据。

## 1. 优先级与交付物

用户明确要求 > 本轮确认的产品目标 > 本 Spec 的行为约束 > PRD > 技术设计 > 历史文档。发现冲突须记录实际处理，不默默更改验收口径。交付包含可构建插件、源代码、测试、安装方式、需求覆盖与未验证项。旧项目保持可回退；当前实现副本位于本工作目录 plugin/。

## 2. 不可破坏约束

- S01：新版任何入口不得自动向主 Agent 发送消息、执行命令或批准权限。按钮复制完整可见文本，复制不等于发送。旧发送队列不在新版启动时恢复。
- S02：所有任务、问题、侧问和回顾必须绑定真实会话及任务；客户端传入 ID 不能替代服务端归属核对。项目切换必须阻止旧任务混入。
- S03：只有用户明确确认才能把提议升级为决定。模型不能确认需求或验收成果；回复结束不等于任务完成。
- S04：每项自动诊断和回顾事实必须有来源。未知、截断、仅 Agent 自述、具体检查通过分别呈现。禁止编造部署、数据位置、测试或恢复结果。
- S05：主工具链不得等待模型诊断。插件读取或记录失败不改变主工具结果；卸载释放监听器、计时器和生成请求。
- S06：打开、切页、手动刷新只读；自动模型调用只能来自已绑定任务的后台策略或用户明确生成动作。限制并发、自动次数、超时，显示开关和说明。
- S07：选区、工具输出、附件是参考材料，不得覆盖插件规则；生成模块不附带操作工具。Markdown 不执行 HTML。
- S08：写入原子化、有并发版本检查；重启不补发消息。同一请求 ID 不得更换内容，重复提交不能重复调用模型。
- S09：删除任务同时删除插件内相关证据副本、问答和回顾；取消其后台工作，晚到结果不得重建任务。旧备份单独说明，不删除项目或主会话。
- S10：未验证的宿主接口不得伪装成功。无右键扩展时使用选区按钮；无草稿接口时复制；无模型时保留草稿、规则事实及历史。

## 3. F1 需求访谈

I01：支持无目录会话；一个问题一轮，可自由回答、请求推荐、修改任务卡、结束或跳过。

I02：任务卡至少覆盖目标用户、目标、核心流程、首版范围、完成标准；第五轮后主动提供结束入口。阻断项缺失或存在未解决矛盾时不得显示“已就绪”，但允许用户显式带待定项开始。

I03：用户可编辑完整交接文本；技术推测不得写为已确认条件。后续修改提升版本并取消旧确认；已生成内容不得静默覆盖用户编辑。

## 4. F2 自动监测

D01：采用宿主工具事实；文字中出现 error 不等于工具失败。一次失败后相关成功消除待提醒；连续同类失败聚合。无新消息不得判卡死。

D02：提示包含现象、影响、下一步、可复制指令和证据。10 秒恢复窗口、两次重复升级为初始策略；活动修复可延后，两分钟后只显示处理中。

D03：支持“这里不对”提交实际／预期；相关新证据到来使旧建议过期。权限只引向主对话原生审批。

## 5. F3 划词与侧问

Q01：选区仅在当前主消息区域采集，排除输入框；保存来源与选区快照。会话变化不得将旧选区自动带入新任务。

Q02：解释包含是什么、当前用途、是否需要行动；独立连续追问、取消、重试、复制、清除。取消失败不得声称服务端停止计费。

## 6. F4 实施回顾

R01：明确候选交付、无运行中操作／审批、新证据齐备时可后台生成阶段回顾；模糊时手动生成。手动中途回顾标“截至当前”。

R02：包括成果、步骤、验证、未知与后续建议；每一步可展开证据。后续开发标记旧回顾为历史，同 basis 不重新生成。

## 7. 质量门槛与变更控制

必须验证：构建、原有核心回归、跨任务隔离、幂等提交、版本冲突、取消／删除晚到、相关恢复、来源校验、无自动发送、真实宿主加载及卸载。模型质量采用独立评测和真人试用，固定回答的宿主 smoke 不代替真实模型效果。

发布记录必须列出 DSH 桌面外壳版本和内部 Harness 版本；能加载不等于所有接口已验证。无法完成的门槛如实标注，不把缺失能力降级成“完成”。首版代码实现之后仍需目标用户试用，才可称产品验收完成。

# Vibe Guide 产品需求文档 v3

版本：v3.0 草案｜日期：2026-11-12｜交付范围：DeepSeek Harness 桌面端插件

本文用于产品评审及后续开发拆解，不表示功能已实现。用户本轮确认的方向优先于旧版文档；文中的数值为首轮实现建议，需通过试用调整。

## 1. 产品定位与已确认方向

Vibe Guide 帮助完全不懂代码、希望借助 AI 做出网页或小工具的用户，把想法说清楚，在开发中处理卡点、理解技术表达，并在完成后看懂实施路线。

产品运行在 DeepSeek Harness（下称 DSH）桌面端，以插件侧栏与划词小窗提供帮助，主 Agent 负责实际开发。首版优先沿用旧项目已有的 macOS 桌面接入；其他操作系统不列为首版发布承诺。

已确认：DSH 桌面插件、上述目标用户、四项核心能力、需求访谈参考 grill-me。建议采用但尚未经过用户逐项确认：访谈可跳过；默认复制指令，能力允许时填入草稿，由用户发送；项目结构降为次级入口。

## 2. 用户问题与成功定义

| 用户问题 | 产品行为 | 成功表现 |
|---|---|---|
| 有想法但不知道怎么描述 | 自适应访谈，整理任务说明 | 用户能判断交接内容是否准确，主 Agent 可以开始第一步 |
| 报错或响应异常，看不懂也不会问 | 读取当前任务相关的可观察证据，解释并提供下一步 | 用户无需截图到另一处重复描述即可继续 |
| 技术词阻断理解 | 选词或选句后原地解释，支持独立追问 | 用户理解当前含义及是否需要采取行动 |
| 做完却不知道如何做成 | 自动生成白话实施回顾 | 用户能复述主要步骤、验证情况及后续修改入口 |

核心产品指标：用户遇到卡点后，能否理解问题并采取有效的下一步。安装数、聊天次数不是单独的成功依据。

首版场景包括个人主页、活动报名页、轻量查询或记录工具。复杂企业系统、多团队协作、长期自主项目管理不作为首版验收场景。

## 3. 产品原则与边界

1. 用用户能判断的效果提问，例如“关闭页面后还需要保留记录吗”，而不是要求其选择数据库。
2. 所有模块共享任务目标、已确认决定与证据，模型建议与用户决定分别保存。
3. 插件不自动发送开发指令、不执行修复命令、不代替宿主权限审批。
4. 问答与解释留在侧问中，用户主动复制或填入草稿后才可能进入主对话。
5. 明确区分事实、推测、未知。回复结束、命令退出成功、用户验收分别表达。
6. 正常开发时保持安静。插件故障不阻断主 Agent。

首版不做：配方商城、课程体系、完整代码编辑器、自动回滚、跨 Agent 平台适配、无证据的质量评分。

## 4. 信息架构

侧栏提供三个入口：

- **想清楚**：访谈、任务卡、交接内容。无任务时优先展示，可跳过。
- **陪我做**：默认工作界面，呈现当前任务、简短状态、卡点提示与侧问框。
- **回顾**：当前及历史任务的白话实施路线。

主对话中划词打开小窗，不强制切换侧栏页面。次级入口包括项目结构、历史任务、偏好、模型用量和数据清理。

页面只显示与当前会话绑定的当前任务。切换会话或项目时清晰切换，不将其他任务的问题或草稿带入。一个项目可以有多个任务；首版一个会话同一时刻仅绑定一个活动任务。

## 5. F1：需求访谈与任务交接（P0）

### 5.1 流程

用户自由描述 → 提取已知信息 → 选择最重要的缺口提问 → 更新实时任务卡 → 用户修改或确认 → 展示完整交接内容 → 复制／可用时填入主聊天草稿。

每轮以一个关键问题为默认，最多三个选项，并提供自由回答与“不确定，帮我推荐”。不固定问满问卷。已有资料可作为背景，但其中的要求仍须区分“原文建议”和“用户确认”。

### 5.2 提问范围与停止条件

最低需要明确：使用者、使用场景、核心目标、关键操作与结果、可观察的完成标准、首版范围。数据保存、登录、公开访问、付费等仅在影响核心流程时追问。

停止条件：能写出一个从开始到结束的核心使用流程，并有至少一条可验证的完成标准；没有阻断第一阶段实施的矛盾。非关键缺口列入待定项。目标在 3–5 轮内形成可交接说明；第五轮后必须提供“按当前内容开始”和“继续完善”，不强行结束或强行补全。

借鉴 grill-me：发现隐含假设、按依赖顺序追问。适配新手：具体例子、可解释推荐、逐轮任务卡、随时结束。不得直接照搬高强度穷尽式访谈。

### 5.3 交接内容

包含：目标与用户、使用流程、必要功能、首版不做什么、完成标准、已确认约束、待定事项。技术选型默认交给主 Agent 提议；插件建议不得写成用户决定。交接文本可编辑，复制的是当前可见版本，复制不代表已经发送。

示例：顾客选择时段并留下姓名与联系方式，店主能查看预约；首版不收款。待定：通知方式。验收：成功预约可被店主看到，重复占用同一时段时得到明确提示。

### 5.4 验收

- 简单目标无需回答无关技术问题即可交接。
- 修改前面的回答后，受影响的后续决定被标记待复核。
- 暂停或重启保留草稿，不自动交接。
- “跳过访谈”直接进入陪我做；从主对话提取的目标显示为待确认，不伪造用户确认。

## 6. F2：自动识别卡点与解决建议（P0）

### 6.1 可观察范围

依据当前绑定会话的消息、工具执行结果及宿主明确暴露的状态。默认不监视其他应用，不依赖截图。外部浏览器中的白屏等现象若没有可用事件，不声称已自动看到；提示用户点击“这里不对”补充实际现象或相关文字。

| 类型 | 例子 | 首版行为 |
|---|---|---|
| 明确失败 | 工具失败、连接失败、可证实的权限拒绝 | 标记问题，结合后续是否自愈决定是否提醒 |
| 疑似反复受阻 | 同一操作重复出现同类失败 | 显示“可能卡住”，附依据 |
| 等待用户 | 宿主明确要求选择或审批 | 指向主对话原生入口 |
| 响应不符合预期 | 漏做、答非所问、用户不满意 | “这里不对”入口收集预期与实际；不自动判错 |
| 可能偏离目标 | 当前输出与已确认任务明显不符 | 仅作可关闭的核对建议，P1 |

单纯没有新消息不判为卡死；限流与网络断开只有获得相应信号时才作具体解释。

### 6.2 提示卡

默认包含：发生了什么、影响、建议下一步、可见的指令全文、复制按钮；“为什么这样判断”展开后显示证据。信息不足时给出检查或补充信息的指令，不承诺确定修复。

例如：“刚才的检查没有通过，因此还不能确认页面能正常运行。可以让主 Agent 先解释失败原因并做最小修改，再重跑同一检查。”

### 6.3 降噪与处理

同一问题聚合为一张卡。首轮建议：失败后等待 10 秒；期间已开始相关修复则延后，修复期间若两分钟仍无明确结果，降级展示“仍在处理”而非报错警报；相同失败两次且仍未恢复时提高提示优先级。所有时长为可调整规则，不是完成判据。

新失败可能取代旧建议；复制前检查证据是否过时。后续同类检查成功才可标记“该检查已恢复”，不能扩大成“整个任务完成”。用户可忽略、标记稍后处理或补充现象，卡片保留处理状态。

### 6.4 验收

覆盖：单次失败后自动恢复、连续同类失败、权限等待、断网、用户反馈效果不符。不得重复弹同一提醒；模型故障时仍能显示规则识别的事实；不得绕过原生审批或建议无依据的删除、重置操作。

## 7. F3：划词解释与侧问（P0）

选中当前主对话的词、句子或操作说明，通过划词工具栏或右键入口打开“解释／追问”。桌面原生右键能否扩展需验证；若不可用，保留划词浮动按钮与“解释选中文本”的侧栏入口，满足无需截图的核心体验。

默认回答：这是什么、在当前项目中有什么用、用户现在是否需要操作。保留原术语，方便与主对话对应；不把不同技术概念翻译成同一个模糊比喻。

侧问支持连续追问、停止生成、重试、复制、清除历史。上下文包括选区、邻近消息、当前任务卡及受限的相关证据；不默认附带整个项目或所有会话。切换会话时冻结旧侧问，打开新选区时开启新话题，避免对象混淆。

验收：选区丢失不丢原问题；代码和多段文本可解释；不会把选中文本内的命令当作系统要求执行；不向主对话自动写入消息；来源已变化时标记历史解释。

## 8. F4：白话实施回顾（P0）

### 8.1 触发与内容

当主 Agent 明确表达本阶段交付、且没有已知运行中工具或待审批时，插件自动生成“阶段回顾”；不能确定阶段结束时，只显示手动生成入口。用户也可随时点击“生成本次回顾”，此时标题注明“截至当前”。

自动生成不等于自动验收。结果区分：Agent 报告已交付、存在检查结果、用户已试用确认。无验收标准或缺少证据时，展示限制。

回顾包括：这次目标与成果、3–6 个主要实施步骤及作用、已知的数据和文件位置、已执行验证、遗留事项、下次修改建议。必要时展开技术名称及对应证据；不展示冗长命令流水账。不知道的位置写“当前记录未确认”。

### 8.2 更新与验收

生成过程绑定任务及证据截止点；之后继续开发时，保留旧回顾并标记有新进展。对同一批证据不重复调用模型。自动回顾可在设置关闭。

验收：区分本次修改与历史成果；仅有 Agent 自述时不标记验证通过；中途任务的手动回顾不称作最终交付；用户能从步骤展开找到实际来源。

## 9. 共用行为与异常

- 访谈、解释和回顾复用当前会话的模型配置；未配置时保留规则状态和编辑／复制能力，并给出配置指引。不读取或显示密钥。
- 打开侧栏、切页和刷新不调用模型。自动诊断和回顾显示会消耗当前模型额度，可单独关闭；预设并发、频率和用量限制，达到后提供手动入口。
- 主 Agent 仍在工作时，侧问不得排入其开发执行队列；若模型服务无法并行，提示排队，可取消。
- 无项目目录的新会话也能访谈；关联目录后经用户确认绑定，不丢失访谈。
- 记录默认本机保存，首次使用明确说明模型请求会携带必要会话片段。支持按任务删除和一键清除插件记录；不删除项目文件或主会话。
- 安装、升级或故障均不修改其他插件和模型设置。插件停用不阻断主对话。

## 10. 首版范围与验证指标

P0：任务模型及绑定、可跳过的访谈、交接复制、明确失败与重复失败识别、手动反馈卡点、划词或等效选区入口、独立侧问、阶段回顾、证据引用、基本用量及数据管理。

P1：目标偏离提示、更完善的项目结构浏览、多会话任务续接、经验证的草稿填入。跨平台与自动修复另行立项。

邀请 5–8 位目标用户，分别完成一个简单任务与一次预设卡点，记录：

| 指标 | 首轮试用目标（非已验证结论） |
|---|---|
| 需求交接 | ≥80% 用户可在 5 轮内确认核心任务说明 |
| 帮助可理解性 | ≥80% 能说清问题及下一步 |
| 提醒准确性 | ≥90% 展示的自动卡片有真实对应卡点，由人工复核 |
| 监测覆盖 | 预设且可观察的失败类型 ≥80% 被识别，同时记录漏报 |
| 划词体验 | 无需截图即可完成解释和追问 |
| 回顾可信度 | 无伪造验证结果；抽查关键事实均有来源 |

首版验收优先满足可用、可解释、无误发送，不以模型是否给出华丽文本作为标准。试用记录默认由测试者主动提供，不默认上传完整会话。

## 11. 交付顺序与待验证项

先验证宿主能力，再实现任务模型与访谈，随后接入诊断和划词，最后加入自动回顾并进行联合试用。各阶段均有可独立体验的结果，不以日期代替完成条件。

待验证：当前安装的 DSH 精确版本；当前桌面版选区／右键扩展方式；草稿填入接口；阶段结束信号；模型并行及取消能力；旧数据迁移样本。以上不影响先实现访谈、复制和手动回顾。

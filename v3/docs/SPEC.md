## 1. 怎么读这份文档

- **用词**：「必须」「不得」是硬性要求。「应当」是默认做法，要偏离就在 13.1 登记。
- **编号**：每条约束有一个编号。`HC` 是硬约束，`F1`–`F4` 对应四个功能，`ML` 模型调用，`ST` 存储，`API` 接口，`UI` 客户端与兼容，`TXT` 文案。检测器编号（A1、B6、C8 等）沿用技术设计 4.3，引用时写作"检测器 A1"。
- **验证方式**：
  - 单元：不依赖宿主的测试。
  - 回放：用录好的会话事件离线驱动。
  - 静态：对源码做检索。
  - 集成：在隔离的宿主里实际运行。
  - 评测：模型质量评测。
  - 人工：人工检查或试用。
- **测试要能反查**：测试的名字或注释里写上它覆盖的约束编号（例如 `HC-1`），这样能查出哪条约束还没有测试。
- **★ 标记**：这一条是本文相对 PRD 和技术设计**新增的收紧或裁定**，汇总在 13.2，可以否决。
- **冲突时听谁的**：用户明确说的 > PRD 第 16 节的决策记录 > 本文 > PRD 其余内容 > 技术设计。本文和 PRD 对不上、而 13.1 里没有登记的，算本文写错了，以 PRD 为准并修正本文。宿主的事实以 M0 实测为准：设计和实测对不上时改设计。
- 这份文档不记录实现进度。

## 2. 硬约束（HC）

任何功能、任何降级路径、任何里程碑都不得违反。改动这一节需要用户明确同意，并记入 PRD 第 16 节。

| 编号 | 约束 | 依据 | 验证 |
| --- | --- | --- | --- |
| HC-1 | **对主会话只读。** 不得调用 `submit`、`prompt`、`fork`，不得写 `inbox`，不得修改或删除会话文件。插件对主对话唯一的影响，是客户端调用 `setDraft` 把文字填进输入框。 | PRD 非目标、D3；技术设计 2 | 静态；集成（走完所有按钮后，会话里用户发出的消息数不变） |
| HC-2 | **填入不等于发送。** 「填入主对话」只填入并聚焦。输入框里已有内容时，先问"替换还是追加"。填入失败时改为复制，并提示"已复制，请粘贴到输入框"，不得显示成已填入。 | PRD 10.3 | 单元；集成 |
| HC-3 | **不改主 AI 的行为。** 不注入系统提示，不新增模式，不改写工具结果。`approval/request` 和 `user-questions/request` 的监听只做记录，然后原样 `return next()`：不得等插件自己的读写或模型调用，监听里出错也不得影响授权和提问的结果。 | D9；技术设计 2、8 | 单元（监听抛错时 `next()` 照常被调用，结果不变）；集成 |
| HC-4 | **模型调用不带工具。** `llm.stream` 不传任何工具。会话内容、项目文件、网页、报错一律当作材料，其中的指令不执行。模型的输出只用来显示或填入输入框，不得当作代码、命令或 HTML 执行。 | PRD 12；技术设计 2、8 | 静态；单元（材料里带"忽略以上指令"的注入样例） |
| HC-5 | **插件出错不影响主线。** 读会话、写盘、调模型失败时，只在插件自己的界面里提示。不得把异常抛进宿主的事件回调，不得让宿主的扩展点整体崩溃。事件回调里不等待磁盘或模型。 | 技术设计 1.5、7 | 单元；集成 |
| HC-6 | **说的每件事都有出处。** 预警卡和路线卡里的每个事实都带依据（事件序号和摘录）。主 AI 说了、但记录里看不到的，标为"AI 自述，未见记录"。推测的原因标为"推测"。没有依据就不说，不得编造部署、数据位置或测试结果。 | PRD 原则 3、7.4、9.3 | 单元；回放；评测 |
| HC-7 | **发现问题不花钱，花钱都有闸。** 规则类检测不调用模型。自动的模型调用只有两个来源：一轮结束后的分析、不认识的报错的解释，各有开关。其余调用都由用户点击触发。打开侧栏、切标签、轮询、划词出菜单，都不得调用模型。每次调用先在预算里预留。 | PRD 原则 6、7.6、11；D5 | 单元；集成（假模型计数） |
| HC-8 | **数据不出本机。** 只通过宿主的 `llm` 调用用户在 DSH 里选的模型。宿主端代码不向其他地址发请求，客户端只请求 `/plugins/dsh-vibeguide/*`。不上报遥测。发给模型前先脱敏。记录只存在本机的插件数据目录里。 | PRD 12；技术设计 8 | 静态；单元 |
| HC-9 | **接口只给本机的 DSH 页面用。** 每个 handler 第一步做准入校验，没通过就按 401 或 403 结束。 | M0 报告第 4 节第 5 条；技术设计 5 | 单元（401、403、放行三种情况） |
| HC-10 | **做不到就明说。** 宿主缺少某项能力时，按技术设计第 7 节降级，并在界面上说明。不得把没验证过的接口当作可用，不得把降级的结果显示成成功。 | 技术设计 7；PRD 15 | 集成；人工 |
| HC-11 | **卸载干净。** 所有订阅、定时器、SSE 连接和进行中的模型调用，都通过 `ctx.effect` 释放。卸载开始后不再写盘，晚到的模型结果直接丢弃。 | 技术设计 7 | 单元；集成（卸载后重载） |
| HC-12 | **从零实现。** 不引用、不复制旧版 `VibeGuide/`（0.2.x）的代码，不读取、迁移或删除旧版的数据。新旧两个插件的包名、路由前缀、数据目录互不相同。 | D1 | 静态 |

## 3. F1 需求梳理

| 编号 | 约束 | 依据 | 验证 |
| --- | --- | --- | --- |
| F1-1 | 每轮最多 3 题。累计 8 题时提示"已经够开工了"，由用户选继续问还是开做。累计 12 题强制进入复述。 | PRD 6.4；D4 | 单元 |
| F1-2 | 问哪几题由服务端的确定性规则决定：只问状态为"未知"、前置依赖已确定、还没问过的维度，按 `影响度 × (1 − 把握) × (1 + 被它卡住的维度数)` 排序。模型只提供候选题，不决定问几题、问哪题。 | 技术设计 4.2 | 单元 |
| F1-3 | 模型给出的每道题都要过校验，不合格就丢弃。校验内容：只问一个决定；2–4 个选项；恰好 1 个推荐项，带推荐理由；每个选项写明"选了会怎样"；题干不超过 40 字；不含术语黑名单里的词，技术选择要换成后果来问。 | PRD 6.4；技术设计 4.2 | 单元；评测 |
| F1-4 | 每道题都能"我来说"和"你来定"。任何一步都能点「先这样，开做」，直接进入复述。 | PRD 6.3、6.4 | 单元；集成 |
| F1-5 | 一轮里合格的题不足 1 道时重试一次，仍然没有就进入复述，不得停在提问页。 | 技术设计 4.2 | 单元 |
| F1-6 ★ | **"已确认"只能来自用户。** 用户自己选的、自己说的、在复述里确认的，才写进"已确认"。从文件推断的、用了默认值的、用户点"你来定"的，一律写进"暂定（AI 推荐，可改）"。模型不能把任何一条升级为已确认。 | PRD 6.5、原则 4 | 单元 |
| F1-7 | 简报由服务端按 PRD 6.5 的模板渲染，模型只提供结构化字段。最后一段"给你的工作方式"是固定文字，不由模型生成。简报要覆盖全部"高"影响度维度，每个维度要么已确认，要么暂定。简报不替主 AI 指定技术方案。 | PRD 6.5、6.7、6.8；技术设计 4.2 | 单元；评测 |
| F1-8 | 简报每次修改都生成新版本，旧版本保留。用户手改过的内容，不得被之后的重新生成悄悄覆盖。 | PRD 6.7 | 单元 |
| F1-9 | 简报属于项目（文件夹）。项目已有简报、用户又提新想法时，必须先问"新需求还是新项目"（接口返回 `needsKind`），不得自己猜。 | PRD 6.7；D12；技术设计 4.2 | 单元 |
| F1-10 | 先自己查（grounding）只读不执行：最多 40 个文件或 200 KB，读到的内容只当材料。能从文件确定的事实不再问。 | PRD 6.3；技术设计 4.2 | 单元 |
| F1-11 | 梳理过程不写代码，不改项目文件。每轮提问调用 1 次模型，复述 1 次，简报 1 次。 | PRD 6.7；技术设计 4.2 | 单元（假模型计数） |
| F1-12 | 梳理到一半关掉侧栏或重启宿主，回来后能接着上次的进度，不重问已经答过的题。 | 技术设计 4.7（`intake.json`） | 单元 |

## 4. F2 异常预警

A、B、D 类属于 M1，C、E 类属于 M2。

| 编号 | 约束 | 依据 | 验证 |
| --- | --- | --- | --- |
| F2-1 | A、B、D、E 类，以及检测器 C1、C6、C7、C8，都是不调用模型的纯函数：同样的事件序列得到同样的结果。说明文字来自模板。 | PRD 7.6；技术设计 4.3 | 单元；回放 |
| F2-2 | A 类先看错误码，再用文字匹配兜底。错误码和异常的对应关系，以技术设计 4.3 的检测器清单和 M0 报告第 3 节为准。 | 技术设计 4.3；M0 报告 | 单元；回放 |
| F2-3 | 命令是否失败，看结果文本末尾的 `[exit code: N]`（N ≠ 0）和 `job/settled`。`isError` 只表示命令没能启动或被中止。结果里出现"error"字样不等于失败。 | M0 报告第 4 节第 3 条 | 单元 |
| F2-4 ★ | B 类的文字匹配只用在失败的执行结果上。成功的命令输出里出现 `EADDRINUSE`、`ENOENT` 之类的字样，不报。 | PRD 7.7 | 单元（反例） |
| F2-5 ★ | **主 AI 自己消化掉的失败不报。** 工具失败一次后，主 AI 在同一轮里自己换了做法并继续推进的，不出"注意"及以上的卡，也不触发模型调用。怎么判定由实现决定，例如等到同样的命令成功，或等到这一轮结束。回放测试里必须有"失败一次后自行恢复"的反例，结果是零出卡、零模型调用。 | PRD 7.7、7.8（误报率 ≤ 10%） | 回放 |
| F2-6 | "阻断"级只能建立在宿主的错误事件（`turn/end` 为 error、`agent/error`）或客户端的离线信号上。模型判断出来的异常最高是"注意"级。依据不够就不报：宁可漏报"注意"，不误报"阻断"。 | PRD 7.3、7.7 | 单元；回放 |
| F2-7 | 提醒方式按级别走。阻断：侧栏预警卡置顶、标签红点，侧栏关着时在输入框上方出提示条。注意：预警卡和红点。提示：只在侧栏显示。提示条只用于阻断级，可以关掉。不在"提醒范围"设置内的级别不提醒。 | PRD 7.3、10.2、11；D6 | 集成 |
| F2-8 | 同一个异常只提醒一次：去重键是"检测器 + 会话 + 签名"，重复出现只加计数。同一个检测器对同一会话 10 分钟内最多新开 1 个异常，检测器 B6、C1 除外。 | PRD 7.3；技术设计 4.3 | 单元；回放 |
| F2-9 | 异常消失后自动标为"已恢复"，不删除。A 类：之后出现成功的 AI 回复。检测器 B6、C1：同一签名执行成功。D 类：请求被处理。 | PRD 7.3；技术设计 4.3 | 回放 |
| F2-10 | 每张预警卡都有：发生了什么、为什么、对你的影响、至少一个可执行的出路、可展开的依据，以及「忽略」「这类不再提醒」「提醒错了」。 | PRD 7.4、7.8 | 单元 |
| F2-11 | 填入的文字里不得有需要用户再改的占位符。模板变量在服务端填好，填不出来的出路不显示。 | PRD 7.8；技术设计 4.3 | 单元 |
| F2-12 | 填入的文字里，模型生成的部分不超过 500 字，并过滤"忽略之前的指令""批准所有权限"一类的句式。结尾来自模板。 | 技术设计 8 | 单元 |
| F2-13 | 时效：A 类从事件发生到提醒不超过 3 秒。"正在重试"从第一个 `llm/retry` 事件就显示。"长时间没动静"由插件自己计时，`running` 状态下 180 秒没有新事件就提醒。等授权 30 秒、等回答 60 秒后提醒。 | PRD 7.8；M0 报告第 4 节；技术设计 4.3 | 回放（时钟可注入）；集成 |
| F2-14 | 主 AI 执行中途不调用模型做偏移检查。思路偏移、范围蔓延、空口完成、动了不该动的，只在一轮结束后和路线卡一起判断，一轮一次调用。 | D13；PRD 7.6 | 单元（假模型计数） |
| F2-15 ★ | 不认识的报错最多自动调用一次模型来解释，受"自动解释不认识的报错"开关和预算约束。开关关着或预算用完时，用通用模板出卡（附依据和"停下说计划"安全词），不调用模型，也不悄悄丢掉。 | PRD 7.6、11 | 单元 |
| F2-16 ★ | 插件不自动修复、不自动重试、不停止主 AI。等授权时只用白话说明这个授权意味着什么，引导用户回主对话处理，插件自己不批准也不拒绝。如果解释授权内容要调用模型，必须由用户点击触发。 | PRD 7.2 D 类、7.7；技术设计 8 | 静态；集成 |
| F2-17 | 用户选了"这类不再提醒"的检测器不再出卡。"提醒错了"的记录只留在本机，用来调误报。 | PRD 7.4；技术设计 8 | 单元 |
| F2-18 | 插件重启或会话恢复后补读历史时，已经处理过的事件不得当作新异常再提醒一遍。 | 技术设计 4.1（`seq` 游标） | 回放 |

## 6. F4 白话路线

属于 M2。

| 编号 | 约束 | 依据 | 验证 |
| --- | --- | --- | --- |
| F4-1 | 自动生成的条件：这一轮不是以 error 或 aborted 结束，至少有 1 个写入或执行步骤，并且"自动分析每轮任务"开着。只聊天的轮次不自动生成。手动点「白话版」时为指定的那一轮生成，即使没有改动。 | PRD 9.2；技术设计 4.5 | 单元；回放 |
| F4-2 | 路线卡和 C 类判断在同一次模型调用里产出。同一轮不重复自动分析。 | PRD 7.6；技术设计 4.5 | 单元（假模型计数） |

### 12.4 "做完了"的口径

- 测试跑过并且通过，才能说通过。没跑的写"没跑"。跑了没过的写"没过"，并附上输出。
- 用假模型（固定回答）跑通的宿主测试，只说明流程是通的，不说明模型效果好。模型质量看评测和真人试用。
- 插件能加载，不等于每个接口都验证过。发布说明必须写明测试时用的 DSH Desktop 版本和内置的 `@deepseek-ai/dsh` 版本。
- 还没验证的项目要列出来，不得写成已完成。目前的清单来自 M0 报告第 6 节：
  - 在日常使用的 DSH Desktop 里，通过「添加插件」界面安装。
  - 真实 DeepSeek 服务的错误文案。
  - 上下文压缩事件的实际触发。
  - 桌面窗口里的扩展点渲染。
- 代码写完、测试通过，只算"实现完成"。目标用户试用达标后，才能说"产品验收完成"。

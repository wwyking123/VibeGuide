| 能力 | 当前实现及边界 |
|---|---|
| 原生侧栏 | Host 级服务、Client bundle、右侧唯一 VibeGuide Tab；对话顶栏按钮和右栏开始页入口。空白新会话的原生顶栏会隐藏自定义动作，仍可从右栏开始页进入。 |
| 提问布局 | 不展示主对话原文或“查看依据”，不添加替代求助入口；现有提问框固定底部。打开和刷新不请求讲解。 |
| 当前会话 | 从宿主不可变 observation cut 读取；项目按当前真实目录标识，使用当前 preset/model 投影；不把压缩摘要或继承的未答原题当作当前用户输入。 |
| 按需解释 | 通过宿主模型路由独立 prepareCall；没有业务工具，打开与刷新不生成解释；同一依据有效缓存，重复请求去重，限制并发、输入和输出，支持超时/取消。 |
| 原题解释 | legacy tool/call + timed projection；真实来源序号与派生问题/选项身份；解释只带选中的那一道题。侧栏提示回主对话原卡作答，不代答。 |
| 失效显示 | 会话有新进展，旧讲解标为当时讲解；同会话切换项目清理旧项目视图，在途结果不能进入新项目。Basis 现覆盖会话、模型/题目、实际操作结果及有界文件指纹；旧讲解恢复时重新核对。指纹范围不是完整依赖环境或业务需求范围。 |
| 单向阀接线 | 隔离 v2 预设仅增加静态 core.md，主 AI 工具与标准模式一致，无旧动态记录注入/记账工具。旧安装版仍保留原链路，尚未迁移用户数据。 |
| 统一输入与澄清 | 原输入框新增 submit 通道：明确追问只解释，明确修改直接转交，含糊或混合表达澄清，原题答案与权限回答回主入口。采用保守确定性规则，不让模型猜测决定是否发任务；复杂表达可能多问一次。 |
| 持久修改转交 | 输入、首次原话、所有澄清补充和 Delivery 同次保存；记录 dispatching 后才调用宿主 queue。显示正在发送、已排队、已送达、待核对或未发送成功。不会把接收等同于执行或验收。 |
| 去重与恢复 | 稳定请求 ID 绑定项目、会话与完整内容；浏览器草稿保留同一 ID；热重载恢复 pending，dispatching/unknown 只对账不重发。核对原生 rpcId、原文及接收项目，重复或内容不符显式标为待核对。 |
| 实际操作状态 | 监听真实工具执行与回执，区分读取、修改、检查、等待及空闲；重启不沿用旧的正在执行状态。没有活动工具但宿主仍运行时显示工作中，状态缺失时明确无法确认。 |
| 改动与检查 | 执行前持久化有界文件基线，执行后记录文件指纹变化及原生命令退出结果。命令正常结束不等于功能完成。文件变化、扫描不完整、并发修改或来源不明确时标明检查范围的适用限制。 |
| 本地恢复 | 按项目和会话持久保存操作与主动讲解；单写者锁、原子写与读回、事件任务登记和启动补读。重开载入已保存的讲解，失效的标为历史，不重新生成。不同项目隔离；当前进展保持会话隔离，“了解过的”明确展示本项目其他会话的历史讲解。 |

客户端通过宿主认证后的 `/api` 通道访问自有 Gateway；请求绑定 session resource，并只允许桌面 owner。浏览器不持有模型密钥，也不直接调用模型提供方。边界有输入字段校验，不额外返回绝对项目目录字段；会话原文可能包含路径，秘密过滤只是补充处理，不能承诺识别任意秘密。

## 第一批记录与限制

新数据位于安装器指定的 `<storageRoot>/guide-v1/`，按项目真实目录标识与会话散列分文件；不迁移、覆盖或注入旧续接记录。JSON 保存实际记录；Node 内置 SQLite 仅持有单写者锁，进程退出后自动释放。文件损坏、写入失败、未知结果和记录容量到限均显式报错，不静默清空或覆盖。

后台事件任务先登记后处理，保留宿主事件水位并在启动补读；客户端暂每 5 秒读取快照，不是完整增量订阅。文件扫描最多 500 个文件、总量 8 MiB、单文件 1 MiB，扫描预算 120 ms；单次系统读取不保证硬截止。排除依赖、构建产物、秘密文件、符号链接和插件自己的私有记录。扫描不完整就不能宣称检查仍适用于完整项目。

只把明确的检查命令归为“检查”；复杂组合命令或未知脚本保守处理。历史执行缺少执行前基线或权威退出回执时不补造“通过”。检查版本范围是有界项目源文件，不覆盖外部服务和远程数据。第四批将实际操作候选与具体要求、试用步骤关联，并由用户核对语义覆盖范围；仅命令通过仍不表示用户验收通过。最近检查与改动计数显示在侧栏，逐项操作历史仍是后续功能。

## 代码入口

- `src/guide/plugin.ts`：Host Gateway、工具执行前后钩子、事件队列与启动补读；卸载取消独立请求并释放存储锁。
- `src/guide/progress.ts`：实际操作归类、执行前基线、命令回执、事件水位与失效判断。
- `src/guide/store.ts`：按作用域的私有 JSON 记录、单写者锁、原子替换和读回。
- `src/guide/files.ts`：有界文件指纹、秘密与符号链接排除。
- `src/guide/host/compatibility.ts`：安装器与后台共用的版本清单；目前支持 rc.2、rc.3，未知版本拒绝启动。
- `src/client/rpc.ts`：将后台失联等传输错误转换为可操作的中文说明，保留模式选择提示和取消行为。
- `src/guide/host/adapter.ts`：会话 cut、当前模型、独立讲解、内部 queue 与 receipt 查询。
- `src/guide/host/choices.ts`：当前原题的确定性关联与失效。
- `src/guide/service.ts`：请求校验、依据核对、解释缓存与取消，组合沟通服务。
- `src/guide/intent.ts`：仅基于用户主动提交的原话进行保守分流，不将对话摘录或模型输出当发送许可。
- `src/guide/communication.ts`：输入与澄清记录、持久发送状态机、恢复与对账。
- `src/client/outbox.ts`：提交前保存浏览器草稿和稳定 ID，恢复后不自动发送。
- `src/client/index.tsx`：原生右栏 UI；只通过宿主 RPC 读取与解释。
- `scripts/build-client.mjs`：宿主 ModuleLoader 格式，React 由宿主提供，不打包第二份。
- `scripts/desktop.mjs`：保留原安装路径；`guide: true` 构建 v2 组合，`install-desktop.mjs --guide --upgrade` 可更新已有安装。
- `scripts/smoke-guide-desktop.mjs`：真实 Host + 本地固定回答模型 + 原生问题卡 + 转交通道验证。

## 复现

要求 macOS，已安装 `/Applications/DeepSeek Harness.app`，内置 Harness 为 `0.2.1-rc.2` 或 `0.2.1-rc.3`。

```sh
npm ci
npm test
npm run smoke:guide
```

UI 开发入口：

```sh
npm run dev:guide
```

它创建临时 DSH_HOME、临时项目与测试会话，使用本地固定回答模型，保留服务供浏览器检查。登录用的临时 URL 写在被 Git 忽略的 `output/playwright/guide-ready.json`，不要发布该文件；在终端 Ctrl+C 退出后清理临时配置。浏览器打开其中的 `url`，进入“VibeGuide 隔离验证”的测试会话，点击顶栏 VibeGuide。

`dev:guide` 不是日常安装命令。试用真实模型时，运行：

```sh
npm run build
node scripts/install-desktop.mjs --home "$HOME/.dsh" --guide --upgrade
```

安装器保留原配置备份、旧插件副本和记录文件，更新唯一的 VibeGuide 模式；没有 `--guide` 时仍安装原项目续接版。重启后新建 VibeGuide 会话，从右栏开始页或对话顶栏进入。新版不挂载旧记账工具和动态上下文，尚未迁移旧记录；主动解释使用会话选择的真实模型并消耗其额度；明确修改会在主对话产生一条真实用户消息，主 AI 后续处理会使用其模型额度。

`smoke:guide` 还会验证旧版升级到侧栏、再次更新、备份原文保留、旧记录与自定义存储路径保留。`node scripts/smoke-guide-desktop.mjs --installed <packageDirectory>` 先把安装包复制到临时目录并重定位插件路径，再在隔离 profile 中加载；测试结束核对正式安装配置逐字节不变，不写日常聊天。

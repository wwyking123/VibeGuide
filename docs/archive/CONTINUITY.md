# VibeGuide 项目续接：开发与试用说明

更新：2026-10-21。代码版本 `0.2.0-alpha.1`；宿主限 macOS DeepSeek Harness `0.2.1-rc.2`。项目续接已合并到唯一的 VibeGuide 模式；尚未通过完整真实模型行为与用户理解验收。

## 使用体验

安装后，新建会话选择 **VibeGuide**。继续在原来的聊天框里说需求。只有笼统想法时先澄清关键使用流程和规则，等待回答再开发；需求明确时正常推进。在关键要求和阶段结果出现时保存项目记录。关掉会话，在同一工作区创建另一个 VibeGuide 会话，可以从最近成功保存点继续。

例如先说“报名名单只有组织者可见”，再修改人数限制和样式。新会话说“继续报名项目”时，AI 能读取此前要求和下一步，并核对相关文件。说“更正一下，只计算参加者，不计算工作人员，先别改功能”时，应更新理解、保留其他要求，并说明功能尚未改变。这是预期模型行为，接口测试不代替真实对话结果。

可以直接问“你记住了哪些要求”，或说“先暂停这项”“只忘掉这条要求，不改代码”。删除记录与取消功能分别处理。多个未完成任务导致“继续”无法定位时，才需要选择任务。

## 安装与验证

```sh
npm ci
npm test
npm run check:evals
npm run check:continuity
npm run smoke:continuity
```

最后一项需要上述兼容桌面版。所有 smoke 数据在临时目录中，退出后清理；不读取账户配置、不调用模型、不打开浏览器。临时宿主会监听随机本机端口，测试结束关闭。

需要实际试用时，在源码目录运行：

```sh
node scripts/install-desktop.mjs --home "$HOME/.dsh"
```

`--home` 应对应实际 `DSH_HOME`。已有安装时加 `--upgrade`，会备份配置并把旧 VibeGuide/P0 的声明合并为单一 VibeGuide。旧插件文件保留，项目记录沿用原 storageRoot，标准模式与其他配置保留。没有带 `--upgrade` 的重复安装会拒绝覆盖。

桌面宿主没有隐藏旧预设或迁移非空会话的正式接口。合并后，旧 P0 聊天文件保留，但不能原地恢复运行；请在同项目新建 VibeGuide 会话读取最近成功记录。不会修改旧聊天 header，也不把旧聊天完整搬入新会话。既有 A/B 环境不随升级改动；新准备的 B 组使用包含记录能力的统一模式，需记清功能差异。

## 内部职责

| 文件 | 职责 |
| --- | --- |
| `src/continuity/plugin.ts` | 原生预设插件；动态上下文与一个 `vibeguide_project` 工具；绑定宿主项目及用户来源 |
| `src/continuity/sources.ts` | 区分用户原话、原生问题所选/自填答案、助手与普通工具输出 |
| `src/continuity/store.ts` | 项目身份、记录结构、任务状态、纠正/删除、原子保存、版本及文件指纹 |
| `prompts/continuity.md` | 在原生对话中读取、保存、解释异常和区分预期/实际的规则 |
| `scripts/smoke-continuity.mjs` | 真实桌面宿主安装、两个进程间的续接和工具边界验证 |

保留现有白话沟通插件，不增加第二模型或前端。使用宿主提供的服务对象，不引入第二份宿主运行时。P0 保留 31 项标准工具，新增三个项目与偏好工具；工具仅写安装器指定的内部状态目录，不改变项目文件或宿主权限。

项目身份来自 `agent.session.header.cwd` 的真实路径，不跟随 shell 的临时 `cd`。记录位于：

```text
<DSH_HOME>/vibeguide-p0-state/<项目真实路径的 SHA-256>/project.json
```

符号链接别名落到同一项目；复制、移动或更名到另一个真实路径视为另一项目，不自动继承记录。不同 `DSH_HOME` 也不共享记录。内容是本地明文 JSON，含项目要求与必要原话，不是凭据存储。

每份记录有版本、当前/被替代/已删除要求，以及分开的任务。要求含用户来源或明确的假设类别；任务进度是 Agent 摘要。差异、结果入口、检查时间/范围和未检查事项由 Agent 写入 `progress/nextStep`，新增验收记录、共识与偏好机制见 [六项功能说明](WORKBENCH.md)；不提供独立的业务完成判定。

来源只接受当前会话日志中的真实用户消息，或与原生提问调用关联的所选标签/自填文字。稳定消息 ID 由宿主提供，模型只能提供事件序号和引用片段。助手文字、普通工具输出、问题措辞和未选项不能成为用户决定来源。来源真实不保证摘要正确，也不能机械证明这句话授权了暂停、恢复或业务变更。

删除要求时清除其内容、原引用和此前被替代的版本，保留来源指纹与删除标记，阻止从同一旧消息/问题重新提取；会话 fork 保留的消息 ID 也受此约束。独立规格、宿主聊天历史、任务摘要和代码不是同一存储：规则要求同步移除任务摘要里的旧理解，但没有自动语义清除引擎。删除说明不能重复抄入要忘掉的内容。用户重新明确表达时，可以凭新消息恢复要求。

## 保存与异常边界

- 写入携带最近读取版本。排他锁阻止插件写入者互相覆盖；旧版本返回 `conflict`，不自动替用户解决不同决定。
- 内容写入临时文件并同步，再原子替换；同步目录并读回版本/操作号后才返回 `saved`。相同操作号和内容重试返回 `unchanged`，不执行代码变更。
- 替换前失败返回 `failed`；替换后无法确认返回 `unknown`。两者都不能说已记住；先读取核对，禁止重复项目/外部操作。
- 损坏、不支持版本或身份不符的记录不会被当成空项目覆盖；上下文说明读取失败，当前对话仍可打开。
- 锁被占用返回 `busy`。进程被强制杀死可能留下 `write.lock`；P0 不自动抢锁。需要先确认锁内 PID 对应的写入进程已退出，再由维护者移走这一项目的锁并读回核对。未确认前不删除锁、不承诺继续保存。
- 原子保存只协调使用本工具的写入者，不保护任意外部程序直接编辑 JSON。保存点之前尚未记录的内容不保证恢复；关闭窗口不会触发一次必定成功的最终保存。

文件检查只记录 Agent 指定的至多 20 个相关文件，按各任务自己的基线比较内容 SHA-256；不扫描整个项目、不推断修改者，也不自动阻止其他代码工具覆盖文件。外部差异的解释和协调仍由 Agent 执行。路径限制在项目内，拒绝向外符号链接、`.git` 和常见 `.env` 路径；不把原始文件内容写入记忆。文件未变不代表服务仍运行或权限仍有效。

记录上限为 1000 条要求（含历史/删除标记）、1000 个任务和 4 MiB。最近 64 个操作号用于幂等重试，超出窗口不能承诺去重。近期用户来源最多提供 12 项，长消息只展示前 4000 字；更早来源需要通过宿主原始日志定位，不得猜序号。新增上下文按任务选择；未读完的要求明确标记不完整，需用 workspace 分页读完再实施。支持完成任务归档，归档不删除有效要求；游标绑定查询和记录版本。超长原记录不再整体返回。

## 已验证与未验证

2026-10-21，29 项自动测试通过，包括规则/安装/手动隔离、模式合并与配置保留，以及来源、纠正、假设不得替代确认要求、删除防复活、任务切换、跨项目、并发、保存失败/未知和文件边界。

真实桌面宿主 smoke 通过全新安装、旧双模式升级为一个模式、全部原生工具保留、工具 Schema 和 TS/Python SDK 生成、原生已选答案来源、普通模式隔离、上下文刷新、退出进程后重开、纠正、外部文件变化和损坏记录降级。使用合成用户事件与受控文件修改；没有冒充模型完成报名应用。

保存未知的测试在持久替换后主动让读回失败；保存失败使用中断/无效存储等受控条件。它们证明接口分支行为，不证明断电恢复、磁盘硬件可靠性或所有中断时序。

尚未验证：真实模型是否按需保存且正确理解、真实问题卡片 UI 操作、长对话压缩、当前服务失效的对话应对、真实用户对选项后果的理解、用量/时延变化。VG-N01 与 VG-N06 的用户评测结果保持未测，P0 总体验验收尚未完成。

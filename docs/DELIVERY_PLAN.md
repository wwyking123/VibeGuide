# VibeGuide 实施计划

日期：2026-10-15。本文保留当时“不写代码”的规划快照，该限制已被用户 2026-10-18 的开工指示替代。当前已实现规则注入、预设安装和接入测试，模型效果与连续任务仍待验证，详见[开发说明](DEVELOPMENT.md)。首发宿主为 DeepSeek Harness。

本计划依据[原生对话设计](CONVERSATION_FIRST_DESIGN.md)和[首版开发规格](IMPLEMENTATION_SPEC.md)。此前解释侧栏、双向选项同步和第二解释模型不再是首版前提。旧 HTML 仅为对照材料。

## 1. 最小交付

一套沟通规则、一个 TypeScript 插件包、一份 Agent preset、必要的当前任务记录和可复现评测。

首个成功任务必须体现：用户提出目标 → 同一个 AI 直接给出易懂方案 → 只询问必要业务取舍 → 开发与检查 → 用实际结果和未知项交代完成情况。

开发职责留给原宿主，不建设独立聊天应用或默认翻译侧栏。

## 2. 工作包与依赖

| 工作包 | 交付 | 退出条件 |
| --- | --- | --- |
| VG-01 行为规范与案例 | 核心规则、正反例、固定评测场景 | 按用户目标定义合格行为，不按接口倒推体验 |
| VG-02 宿主加载验证 | 固定版本、最小插件、preset、复现记录 | 依赖 VG-01；影响原生回复与提问，保留工具和权限指导 |
| VG-03 连续任务与上下文 | 目标、决定、未知项、来源与版本 | 依赖 VG-02；长对话、恢复、需求变化通过；必要时补持久记录 |
| VG-04 完成与失败说明 | 实际结果与检查依据进入原生回复 | 依赖 VG-02/03；失败不报成功，示意、用户报告和检查分开 |
| VG-05 对照评测 | 固定场景与两类用户任务记录 | 比较原生、简单白话提示和 VibeGuide，检查误解、遗漏和负担 |
| VG-06 打包与交付 | 安装、创建会话、退出/卸载、兼容说明 | 前述验收通过，干净配置可复现，限制可追踪 |

VG-01 可先用轻量 skill 做内容实验。作为持续模式交付时，必须验证每步规则、作用域和生命周期，不能把一次成功对话当成插件完成。

## 3. 技术验证记录

1. 实际目标版本和外部插件加载方式，不只引用研究中的固定提交。
2. 新创建的 VibeGuide 会话与普通会话隔离，相同规则不重复注册。
3. 普通回答、plan 和结构化提问直接使用可理解的语言，保留原生回答路径。
4. 模型、工具和权限能力保留，不要求第二模型或额外 API key。
5. 压缩和恢复后的规则及目标保留，来源缺失时明确未知。
6. 目标变化后的版本处理；跨会话记录不混用，旧检查不冒充当前结果。
7. 配置更新与移除的实际效果，不承诺未验证的既有会话即时切换。
8. 额外输入量、成本和时延；未测量时保持未知。

## 4. 评测与继续规则

十个固定场景见[开发规格](IMPLEMENTATION_SPEC.md)。先冻结目标、事实和严重失败条件，再比较回答。

严重失败包括改变明确意图、未执行说成完成、遗漏关键限制、把业务选择当作额外操作授权。流畅程度不能抵消这些失败。

记录第一份回答是否足够理解、用户能否预测后果、需求能否持续保留，以及额外追问和确认是否增加。覆盖从零开发与已有应用修改。

规则无效时先改内容和提问策略；简单提示效果相同时保持轻量；主要问题是遗忘时优先修复上下文。用户研究必须基于实际观察，不把内部样例评审当作真实访谈。

## 5. 后续协作边界

本轮只更新 Markdown 文档，不创建代码、配置或安装脚本，不安装插件，不修改 HTML。尚未派发实施任务。

以后如安排并行开发，先固定规则与最小记录契约，再分配文件独占范围：

- 规则与评测：`prompts/`、`evals/`。
- 宿主接入：`src/host/`、`presets/` 及对应测试。
- 当前任务记录：`src/context/` 及对应测试。
- 集成负责人独占插件入口、共享契约、依赖、锁文件、打包配置和文档索引。

一个文件同一时间只有一个写者；共享契约变化统一协调。上述是未来建议，不表示已经安排其他 Agent 写代码。

## 6. 工期判断

旧侧栏方案的3–4周估计不再沿用。新方案减少了 UI 和答案转译工作，但长会话遵循、需求保留与效果验证仍需实测。VG-02 完成后根据加载难度、模型表现和试用条件重新估算。

当前交付为可评审的开发规格，不代表沟通规则、插件或验收已经实现。

# 亲自体验：默认模式与 VibeGuide

这是一轮真实使用体验，不是严格盲测或统计实验。A 使用标准模式，B 使用 VibeGuide。先随机选一组，再做另一组；下一个任务交换顺序，减少熟悉任务带来的优势。

从 `0.1.0-alpha.4` 新准备的 B 组包含关键需求澄清与项目记录工具，两组并非仅提示词不同。此前生成的评测环境继续使用各自冻结的旧插件。记录实际版本和能力，不向旧评测环境复制新版或其他组的产物。

## 开始前

使用准备器给出的两个本地链接。它们运行的是已安装桌面版自带的 Harness Web 会话界面，各有独立进程、项目目录、聊天记录、账户凭据副本和浏览器连接凭据。日常桌面窗口仍使用原有配置。

确认两边选中同一个模型、相同思考强度和权限模式。准备器复制当前默认模型设置，模型供应商若改变同名模型背后的版本，无法仅凭这个选择保证权重版本固定。不要在一组中临时更换模型或权限。

两边从相同的项目状态开始，不选择 VibeGuide 源码仓库作为工作区，不引用旧会话，不安装额外插件，也不把任何一组的回答或文件交给另一组。不要把评分表放进任一项目目录。

## 使用已有需求文档

如果已指定两个工作区，可以由你分别发送相同的原始提示词，不需要复制文件。若一个目录里的需求文档或代码已是该组 AI 的产物，应让另一组从原始提示词独立生成，不把先完成一组的结果提供给另一组。

只有使用现成项目或你自己提供的原始材料时，才需要核对两组初始材料一致。开始后不再同步生成的文档或代码。

例如，两边都有 `slouchcat-demo-spec.md` 时，分别发送相同的话：

> 请阅读当前目录里的 slouchcat-demo-spec.md，按照这个需求帮我开始开发。我不会写代码。

保持原始规格不变，观察两组如何解释实现过程、处理不确定条件、提出问题和汇报实际进展。不要为了测试提前修正文档里的歧义，或把另一组已经发现的问题提醒给本组。

## 空项目示例：公司介绍网站

把下面这段完全相同的话分别发给两组：

> 我想给一家叫「青禾设计」的虚构设计公司做一个介绍网站。希望客户能了解我们的服务、看几个案例、认识团队，并找到联系我们的方法。我不会写代码，现在也没有正式图片和文案，可以先用明确标注的示例内容。请帮我开始做第一版。

遇到提问时，按下列固定业务设定回答相关问题；只回答它实际问到的内容，不主动补充另一组让你想到的要求：

- 客户：需要品牌设计服务的小企业。
- 风格：简洁、温暖、可信，以中文为主，手机上也要看得清楚。
- 联系方式：第一版展示占位邮箱和电话即可，不需要真的发送邮件。
- 预算和发布：本轮先在本机体验，不购买服务、不公开发布。
- 技术选择：你不了解技术，希望 AI 结合需求作推荐并解释实际影响。

两组都做到可以看第一版后，再分别发：

> 以后案例需要市场部同事每周自己更新，她不会写代码。这个可以做吗？我需要准备什么？先把使用过程和需要我决定的事情说明白。

如被问到审核要求，统一回答：

> 必须由我看过确认后才能对外发布，审核前公开网站不能变。

如果看不懂，可以正常追问「这个是什么意思，对我的网站有什么影响？」。把追问次数记下来，不需要为了输入完全相同而忍着不问。这一轮比较的是实际使用体验；对话一旦分叉，不能把后续回复当成完全相同上下文的实验。

## 每组结束后先独立记录

在本说明旁边另存自己的记录，不写入 A/workspace 或 B/workspace：

| 观察项 | A | B |
| --- | --- | --- |
| 我是否知道接下来会做什么（1–5） | | |
| 我是否理解所做选择的后果（1–5） | | |
| 为了解释术语而追问的次数 | | |
| 被要求决定自己不懂的技术问题的次数 | | |
| 重复询问已经回答过的问题的次数 | | |
| 明确需求是否被遗漏；具体是哪条 | | |
| 是否分清界面演示与真正能用的功能 | | |
| 最困惑的一句原话 | | |

先记录第一组，再开始第二组，最后比较。不要只凭回答更长、更亲切或网页更漂亮判断沟通质量。保留失败、中断和不满意的回答，不只挑好例子。

## 隔离范围

准备器在 macOS 上为两组设置独立的操作系统文件访问规则：只能读取本组数据及运行所需的公共系统资源，另一组目录、日常 Harness 数据、VibeGuide 源码和评分记录不在可读范围。子进程继承限制；安装前会实际测试直接读取、子进程读取和符号链接读取是否被拒绝。每组也阻止连接另一组的 Harness 本地端口。

这属于针对本地评测污染的隔离，不是两台独立计算机：仍共用系统软件和联网能力。不在两组中接入相同的外部数据库、云端项目或共享文档，不把两组项目通过其他本地服务公开。测试不能证明不存在所有恶意绕过方式。

## 保存和停止

聊天记录保留在本次目录的 A、B 中。默认项目也位于其中；指定已有工作区时，生成的代码保留在你指定的目录。评测数据目录含账户登录凭据副本，保持本地保存，不上传 GitHub。停止两组后再整理对话；分享评测只分享去除个人信息的对话和评分。

在 Finder 中双击本次目录里的「结束评测.command」可停止两组；双击「恢复评测.command」可重新启动并显示入口地址。

重新从零评测时重新执行 prepare，生成新目录；start 只恢复本轮环境，不会清空历史。
